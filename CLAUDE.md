# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Curador CABA · Compras de Tecnología (formerly "Curador CABA Intelligence", renamed 2026-10-31): a fully static dashboard (no backend) for auditing public procurement in the City of Buenos Aires (CABA). It correlates two independent official sources — the Boletín Oficial (norms/actos published day by day) and Buenos Aires Compras / BAC (an OCDS export with real award amounts) — with the explicit goal of surfacing audit signals (non-competitive tenders, vendor concentration, direct-contracting share), not just displaying metrics. `README.md` has the full architecture diagram, data file schemas, and known limitations — this file is about working in the codebase productively, not repeating that.

## Commands

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r runtime/requirements.txt
playwright install chromium           # one-time browser download, needed for bac_aperturas_scraper.py / bac_pliegos_caidos_scraper.py / bac_recurring_vendor_watch.py

# pipeline steps — each reads data/*.json, merges/regenerates, writes back; safe to re-run
python runtime/collector.py                  # scrape today's live Boletín edition -> runtime/output/latest.json
python runtime/data_model.py                 # merge into data/editions.json, norms.json, procurements.json, stats.json
python runtime/procurement_intelligence.py   # -> data/procurement_intelligence.json
python runtime/normative_impact.py           # -> data/normative_impact.json
python runtime/bac_catalog_collector.py      # download+parse BAC's bac_anual.csv -> data/bac_catalog.json
python runtime/bac_aperturas_scraper.py      # headless-browser scrape of BAC's live advanced search (open tech tenders: Publicado + En Apertura) -> data/bac_aperturas.json
python runtime/bac_pliegos_caidos_scraper.py # headless-browser scrape of BAC's live "Desierto"/"Dejado Sin Efecto" tech tenders -> data/bac_pliegos_caidos.json
python runtime/bac_presupuesto_oficial.py    # official budget of each open tech tender (BAC detail page, cached) + 'presupuesto entre los más altos' signal -> data/bac_presupuestos.json
python runtime/bac_recurring_vendor_watch.py # headless-browser check of bac_catalog.json's recurring_direct_pairs candidates against BAC's live search -> data/bac_recurring_vendor_watch.json
BACKFILL_START=7275 python runtime/backfill_boletin.py  # one-off historical Boletín backfill
python runtime/data_health_check.py           # read-only invariant check over data/*.json; exit 1 + Markdown report on any issue

# tests (stdlib unittest, no pytest/jest, no frontend test runner)
python -m unittest discover -s runtime/tests -v
python runtime/tests/test_data_model.py -v   # single file

# frontend — static, no build step; any static server works
python -m http.server 8000
```

There is no linter, no bundler, no frontend `package.json` — `app.js`/`index.html`/`styles.css` are hand-written and deliberately terse (single-line functions), served as-is.

## Amount integrity (mandatory)

Two calculation errors reached the published dashboard on 2026-10-31 with every status `ok` (USD awards silently dropped; SATE911 counted 3× via item variants). Since then:
- **Never publish a change that moves amounts without reconciling it.** Any change to collectors, dedupe, currency conversion, classification, or a regenerated `data/bac_catalog.json` must be reviewed with the `data-integrity-reviewer` agent before merge, and the PR must include an "Impacto en montos" section (the PR template asks for it; CI fails without it when the impact report flags > 10% movement).
- **Tests must encode verified values, not assumptions.** If a test asserts how real data should be grouped or summed, cite the source recomputation in the test comment.
- `data_health_check.py` enforces: per-process reconciliation (`amount_ars` ≤ `monto_reconstruido_ars` × 1.05, reconstructed once per renglón from quantity × unit price, independently of the dedupe key), regressions against `runtime/montos_verificados.json` (1% tolerance), and that any process > 25% of the tech total is in that verified registry. Add entries there only after recomputing from the source.
- CI (`.github/workflows/ci.yml`) runs tests + health check + `runtime/impact_report.py` on every PR to master.

## Architecture

**The pipeline is "git as database."** Every `runtime/*.py` script reads the current `data/*.json`, merges or regenerates in memory, and writes the whole file back — there's no incremental delta storage. Six GitHub Actions workflows write to `data/` and all share `concurrency.group: caba-dashboard-refresh` so they queue instead of racing each other's push to `master`:
- `refresh-official-data.yml` — hourly in business hours (lowered from every 30 min — GitHub throttles/drops high-frequency `schedule` triggers): `collector.py` → `data_model.py` → `procurement_intelligence.py` → `normative_impact.py`.
- `refresh-bac-data.yml` — once a day: `bac_catalog_collector.py` only, with conditional fetch (skips the ~55MB download if the source's ETag/Last-Modified hasn't changed).
- `refresh-bac-aperturas.yml` — hourly in business hours (same throttling reason): `bac_aperturas_scraper.py`, `bac_pliegos_caidos_scraper.py` and `bac_presupuesto_oficial.py`, all headless-browser (Playwright) scrapes of BAC's live transactional site — see the gotcha below before touching either.
- `refresh-bac-recurring-vendor-watch.yml` — once a day (deliberately not hourly: its candidate list, `bac_catalog.json.audit_signals.recurring_direct_pairs`, barely changes between the daily `refresh-bac-data.yml` runs it depends on — scraping BAC's live search hourly for a list that's ~static would just be load on their site for no benefit): `bac_recurring_vendor_watch.py`.
- `backfill-boletin.yml` — `workflow_dispatch` only, for patching historical gaps: `backfill_boletin.py` → `procurement_intelligence.py`. Budget ~30-50s per Boletín edition when picking a range (measured, not estimated).
- `pages.yml` — deploys to GitHub Pages on every push to `master`.
- `check-data-freshness.yml` — weekdays 11:30 ART, read-only: re-dispatches hourly pipelines that didn't run today ("did it run?"), then runs `data_health_check.py` ("does what ran make sense?" — gaps in recent Boletín numbers, scraper rows not matching BAC's reported totals, junk/duplicate rows, non-ok statuses). Each opens/closes its own GitHub issue. When fixing a pipeline bug that produced bad-but-`ok` data, add an invariant there so it can't recur silently.

When a workflow's persist step hits a rebase conflict: `refresh-bac-data.yml`, `refresh-bac-aperturas.yml`, and `refresh-bac-recurring-vendor-watch.yml` auto-resolve in favor of the current run (their output is a full regeneration from a freshly fetched source, so "ours" is always at least as complete); `refresh-official-data.yml` and `backfill-boletin.yml` do **not** auto-resolve (their output is an incremental merge against the prior file, so blindly picking a side could silently drop an edition) — they fail the job for manual review instead. Keep this distinction if you add another workflow that touches `data/`.

**`bac_aperturas_scraper.py`, `bac_pliegos_caidos_scraper.py`, and `bac_recurring_vendor_watch.py` must navigate by clicking a real link, never `page.goto()` the listing/search URL directly.** The shared click-through, grid reading, and pagination for `BuscarAvanzado.aspx` live in `runtime/bac_buscar_avanzado.py` — use it from any new BAC live-search scraper instead of copying it. BAC's transactional site (`buenosairescompras.gob.ar`, not the open-data portal) is ASP.NET WebForms with session-bound ViewState/postback. A plain `requests`-based scraper replicating a captured HAR (exact headers, CSRF token, Referer) still fails — the ViewState is single-use and tied to the session that rendered it, so any replay is already stale. Even a real headless browser `goto()`-ing the listing URL directly gets redirected to `Default.aspx` (confirmed) — it only works when you load the homepage first and `page.click()` the actual `<a>` for that listing/search page, letting the browser generate the postback with a live ViewState. If this stops working, suspect the click-through sequence before suspecting Playwright itself.

**`bac_catalog_collector.py` intentionally has no "failed/cancelled tender" signal — don't re-add one keyed off `bac_anual.csv`'s `tender/status`.** It existed once (`audit_signals.failed_or_cancelled_tenders`) and was removed in favor of `bac_pliegos_caidos_scraper.py`: verified via `HEAD` against the CDN that all 8 files in the `buenos-aires-compras` CKAN package (`bac_anual.csv/json/xlsx`, `tender.csv`, `award.csv`, `contracts.csv`, `parties.csv`, `bac.csv`) share the same `Last-Modified` — the whole bulk-export package is regenerated as one batch, sporadically, so no file inside it can be "fresher" than another. BAC's live "Búsqueda avanzada" (`BuscarAvanzado.aspx`) filters `Estado de Proceso`/`Rubro` server-side against the real transactional database instead, which is why that signal now lives in its own scraper rather than in the CSV-based collector.

**`bac_presupuesto_oficial.py` reads amounts from each process's BAC detail page, not from the grid** (the grid has no amount). To reach a single process, use the *Búsqueda rápida* button `#ctl00_CPH1_btnListarPliegoNumero` with `#ctl00_CPH1_txtNumeroProceso` — the advanced-search button silently ignores the number field and returns the whole estado (cost a full run of 22 wrong lookups to learn). Each process is visited once (cache inside `bac_presupuestos.json`; Publicado ones re-checked every 7 days), with a 3-consecutive-errors circuit breaker. The detail page lists names and DNI of supervisors/evaluators: only monto/moneda/duración/fecha are extracted, never store the page text or commit it as a fixture. The signal compares USD amounts (ARS converted via `fx_bcra.py` at publication date) **within the same procedure family** (licitaciones públicas vs. menores/directas) with robust log-z (median/MAD), flagging z ≥ 2 with ≥ 15 peers — thresholds arbitrary and documented; don't tune them to make a specific case flag. Rank and × median are always shown as context; UI copy must never say "sobreprecio".

**`bac_recurring_vendor_watch.py` reads `data/bac_catalog.json`, it never re-downloads `bac_anual.csv`.** Its candidates come from `audit_signals.recurring_direct_pairs` (organismo+vendor with 2+ direct/limited awards, no time window — a long-term-relationship signal, distinct from `possible_fractionation`'s 90-day burst window). For each candidate it searches BAC's live `BuscarAvanzado.aspx` (TipoProceso=Contratación Directa + Rubro=Informática + Estado=Adjudicado) for an award more recent than `coverage.date_to`, and only flags it after confirming vendor identity on the process's own detail page (`VistaPreviaPliegoCiudadano.aspx` — same-organismo alone isn't enough, a different vendor could have won that one). `normalize_name` in that file is deliberately strict (no internal-whitespace collapsing) — a missed match is preferred over a wrong one, since this feeds an audit-signal UI.

**Two sources, cross-referenced only at the organismo-name level, not per-tender.** The Boletín pipeline (`collector.py` → `data_model.py`) identifies a tender by an expediente number embedded in free text (`proceso_id()`, e.g. `14/IVC/26`, keyed by organismo *sigla*). BAC (`bac_catalog_collector.py`) identifies the same kind of tender by a different scheme (e.g. `416-2702-CME26`, keyed by a numeric organismo code). These do not map 1:1, so don't attempt a direct join on process/tender id — it's a known, documented gap. What *does* work is matching organismo **display names** after normalization (both sources use human-readable names like "Ministerio de Cultura" / "MINISTERIO DE CULTURA") — see `normalizeOrgName`/`bacOrgIndex` in `app.js`, the only cross-source join that currently exists, rendered as a badge in the org ranking.

**`data_model.py` owns every Boletín business rule** — `merge_norm` (anti-regression field merge that never lets a partial re-fetch null out a previously known value, plus `clean_organismo` name normalization), `isproc`/`category` (contratación detection + rubric classification), `proceso_id` (act-to-process grouping, e.g. collapsing a llamado + its circulares + prórroga). `collector.py` and `backfill_boletin.py` both import these rather than reimplementing them — if you change classification/merge logic, change it here once, not per caller. Same principle in `bac_catalog_collector.py`: `classify_technology`/`tech_source` is the one place technology rules live — keywords **plus** BAC's own catalog code (`tender/items/0/classification/id`, prefixes in `TECH_CATALOG_PREFIXES`; added 2026-10-31 for issue #15, it surfaced SATE911, OpenShift, IBM Z16 and other tech the keywords missed — tech awarded went from ARS 21.5B to 46.9B before the -N variant fix below brought it to 26.0B). **`dedupe_csv_rows` collapses `awards/0/items/0/id` -N variants with the same amount** within a renglón: the amount is the award's value repeated per partial delivery, not a per-item value — counting variants separately tripled SATE911 (19.3B vs real 6.6B). Don't revert this to 'variants are distinct items'. Don't add `\bsist\.` to the keywords: it brings surgical false positives. Keyword rules (deliberately requires a qualified phrase like "redes de datos", not bare "redes", after a real false-positive on "redes eléctricas" made it into a merged commit).

**`bac_catalog_collector.py` converts USD awards to ARS, it doesn't drop them.** ~221 deduped awards in `bac_anual.csv` are in USD (USD 9.1M in tech, mostly Agencia de Sistemas de Información — more than all ARS tech awards); until 2026-10-31 they were silently skipped, which hid ASI from every signal and inflated the direct-contracting share (68% → 33%). `runtime/fx_bcra.py` fetches the BCRA's official daily USD rate (public API, cached in `data/fx_usd_ars.json` by covered date range) and each award is converted at its own date's rate (or the last business day before); `amount_usd` keeps the original. An award with no rate is excluded but counted in `summary.fx.excluded_awards_by_currency`, which the UI shows and `data_health_check.py` flags. Bump `COLLECTOR_VERSION` on any parsing/signal change, or the fix stays mute until BA Data re-publishes the CSV.

**`bac_catalog_collector.py` targets `bac_anual.csv`, not the more obvious `bac_anual.json`.** Same CKAN package, same nominal dataset — but the JSON resource is stale (verified against the CDN: it only ever contains Jan-Jun 2022 data despite being periodically re-uploaded with a fresh `Last-Modified`), while the flattened-OCDS CSV has real current data. `find_resource()` matches on the resource **URL**, not the CKAN-displayed `name` field (which is generic/misleading for both formats — don't "simplify" that match back to using `name`).

**Frontend does all aggregation client-side from raw JSON, no server-side pagination.** `app.js` fetches `data/*.json` whole (`cache:'no-store'`, no caching) and does filtering, `proceso_id` grouping, and the BAC organismo cross-reference in the browser (`filteredNorms`/`filteredProcurements`/`groupByProceso`/`renderOrgRanking`). Lists paginate client-side via `normsPage`/`procPage` counters ("Cargar más" buttons), not real pagination — the whole filtered set is already in memory. There's no framework and no build step: edit `app.js` directly and reload. The dashboard is **one HTML page per section** (`index.html` = Hoy, `licitaciones.html`, `senales.html`, `normativa.html`, `panorama.html`, `explorar.html`), all sharing `app.js`/`styles.css`. `PAGES` in `app.js` is the single source of truth: per page, which `DATASETS` to fetch (so Hoy loads ~0.4MB instead of the ~26MB `norms.json`+`procurements.json`+`procurement_intelligence.json`) and which `RENDERERS` to run; the header + nav are built from it by `renderShell()` (no build step, so don't hand-copy nav markup into each .html). To add a section: add a `PAGES` entry and a .html with `<body data-page="...">`. Renderers must tolerate their target elements being absent (guard with `$(id)`/`setText`). Old single-page anchors (`#bac-failed-tenders`, `#senales`, …) are redirected via `ANCHOR_PAGE` — add new cross-page anchors there.

**Audit signal thresholds are arbitrary and documented as such, not derived**: `CONCENTRATION_MIN_AMOUNT` / `CONCENTRATION_HIGH_PCT` in `bac_catalog_collector.py` exist to reduce noise (don't flag a single small purchase as "100% vendor concentration"), not because they're statistically justified. Don't present anything computed from `audit_signals` as proof of irregularity in UI copy — it's a review trigger, and the existing copy is careful about that distinction.
